# Step Together — контекст проекта для Claude

**Читай этот файл первым.** Он описывает актуальное состояние проекта, чтобы
каждая новая сессия сразу понимала контекст.

## Что это

Telegram-бот **Step Together** (@wegrowmarathon_bot) — корпоративный шаговый
марафон для сотрудников компании. Участники ежедневно присылают количество
шагов + скриншот из Google Health (бывший Fitbit), P&C модерирует, начисляются баллы, команды
соревнуются. Маскот и «ведущий» всех диалогов — росток **Stepy 🪴**
(премиум-эмодзи id `5305729158385533791`); его реплики оборачиваются в
`<blockquote>` через `texts.stepy()`. Админ-сообщения (P&C) — без Stepy,
деловым тоном.

- **Марафон: 12 октября — 1 ноября 2026**, таймзона `Asia/Bishkek` (Кыргызстан,
  UTC+6). Даты и TZ — только через env (`MARATHON_START`, `MARATHON_END`,
  `TZ`), дефолты в `bot/config.py`. В текстах даты НЕ зашиты: бот берёт их
  из `texts.marathon_dates()`, Mini App — из `marathon` в `/api/me`.
  До октября 2026 марафон проводился в Узбекистане (Ташкент, UTC+5).
- Проект **уже запущен в проде, есть живые участники** — миграции только
  аддитивные (`ADD COLUMN IF NOT EXISTS`), данные не ломать.
- Язык всего интерфейса — русский. Обратная связь ведёт на P&C Кыргызстана:
  https://t.me/aidanazhanyshbekova (`config.feedback_url`, env `FEEDBACK_URL`;
  в Mini App — константа `FEEDBACK` в index.html, менять обе).

## Ключевая бизнес-логика

- **Правила WE GROW** — по документу «I GROW • WE GROW • WE GROW OTHERS»
  (рынок Кыргызстана). Бот реализует только блок WE GROW (шаги); I GROW и
  WE GROW OTHERS ведутся вне бота.
- **Баллы за день** (`backend/scoring.py`): 5000–9999 → 1, 10000–14999 → 2,
  15000–19999 → 3, 20000+ → 4, меньше 5000 → 0. Больше 30000 — на ручную
  проверку. Ступень 20000+ добавлена 10.10.2026 на идущем марафоне: принятые
  дни пересчитаны разово (`db.rescore_accepted_entries`, флаг
  `migr_scale_20k` в settings, вызов — `main._one_time_migrations`).
- **Командный зачёт** (`db.team_leaderboard`): СРЕДНЕЕ личных сырых баллов
  (дневные + недельные бонусы) активных участников (подтверждён, не DQ) +
  командные очки флешмобов, округление до 0,1. Тай-брейк: больше дней, когда
  ВСЕ активные участники имели принятые 10000+ (`full_days`), затем сумма
  шагов. Дробные баллы показываются через `texts.fmt_points` / `fmtPts`
  (12,5). `/api/team.total_points` — это среднее, не сумма.
- **Команда — ровно 5 человек** из разных функций (`db.TEAM_SIZE`, дефолт
  `teams.capacity`). Разовая миграция 10 → 5 (флаг `migr_team_size_5`);
  переполненные команды видны в `/health` (⚠️) — состав правит P&C.
- **Серия (стрик)** — дни подряд с 10000+ шагов, считается ТОЛЬКО по
  принятым (`accepted`) дням: `db.recompute_streak`.
- **Недельный бонус** — по календарной неделе пн–вс: 5 дней подряд 10000+
  → +2, 7 дней → +4 (высший, один раз за неделю). Пересчитывается при
  КАЖДОЙ модерации (`db.recompute_weekly_bonus`), не только в воскресенье.
  **Бонус засчитывается только с недельным отчётом** (вс 22:00–23:55):
  `weekly_summaries.earned_bonus` — заработанный по принятым дням,
  `bonus_points` — засчитанный (= earned, если есть `reported_at`, иначе 0).
  Во все зачёты идёт только `bonus_points`. `db.recompute_weekly_bonus_change`
  → `BonusChange(old, new, old_earned, earned, reported)`; пуш выбирает
  `texts.bonus_notice`: «заработал +N, пришли отчёт в вс» или «засчитан».
  Отчёт (`steps.on_weekly_shot`) сразу пересчитывает и отвечает
  `texts.weekly_saved`. 23:15 — тем, у кого бонус заработан без отчёта,
  персональный «бонус сгорает» (`weekly_last_call_bonus`); вс 23:55 —
  страховочный пересчёт, пушит только при росте засчитанного. В Excel —
  колонки «Бонус заработан» / «Бонус засчитан».
  **Ручной зачёт отчёта** (технический сбой): карточка участника →
  «📈 Недельные отчёты» (`usrwk:`), по каждой неделе марафона статус и
  кнопка «✅ Засчитать» / «↩️ Снять зачёт» (`db.set_weekly_report_manual`,
  `report_source='admin'`; скриншот участника — `'photo'`, его снять нельзя).
  «Отчёт есть» везде = `reported_at IS NOT NULL`. Участнику — пуш
  `texts.weekly_manual_note`. Принятый день повторной
  отправкой не перезаписывается (`save_submission` → 0).
- **Отображаемая серия** — `db.live_streak_len`: `streaks.current_len` жив,
  только если последний 10000+ день — сегодня/вчера (или вчера на проверке);
  иначе 0. Так же фильтрует `streak_at_risk` (20:00).
- **Модерация**: заявка `pending` → админ Accept / Reject / Warning
  (warning НЕ принимает результат). Баллы и серия участнику идут только
  после Accept. Повторная сдача за день сбрасывает статус в `pending`.
  Карточки уходят в канал проверки, поэтому текст предупреждения бот просит
  **в личке админа**: состояние FSM кладётся под ключ личного чата
  (`admin_settings._private_ctx`), иначе ответ админа не находит хендлер.
  После отправки предупреждения карточка в канале помечается, кнопки
  модерации остаются. Подсказка приходит **тому админу, который нажал**
  (`cb.from_user.id`), состояния разных админов не пересекаются.
- **Админы**: базовые из env `ADMIN_IDS` + добавленные `/addadmin` (ключ
  `extra_admins` в settings). Права проверяются через `settings.is_admin`,
  а рассылки «всем админам» — через `settings.admin_ids()` (env + доп).
  НЕ использовать `config.admin_ids` для уведомлений: доп-админы их не
  получат. Меню команд ставит `bot/commands.py` — на старте, при /addadmin,
  /deladmin и при /start админа (Telegram не даёт задать scope чата, пока
  пользователь не начал диалог с ботом).
- **«👑 Админы» в админ-панели** (`admin.py`, колбэки `adm:admins/adadd/
  adpick/ad/adset`): список админов, добавление поиском по ФИО / @username /
  ID среди всех, кто нажал /start (`find_participants(...,
  with_unregistered=True)`; username пишется уже при /start), снятие и роль.
  Роли: 🛡 админ и 👑 владелец. Владельцы = env `ADMIN_IDS` + `extra_owners`
  в settings (`settings.is_owner/owner_ids`); только владелец назначает и
  снимает владельцев и видит «🧨 Сброс марафона». Env-владельцев из бота не
  снять, себя снять нельзя. Render для смены админов больше не нужен.
- **Ручной ввод результата** (админ-панель → «✍️ Ручной ввод»): поиск
  участника → календарь дней марафона → число шагов → подтверждение.
  Скриншот не нужен, запись создаётся сразу `accepted` с `source='admin'`,
  участнику уходит пуш (`texts.manual_entry_note`). Дни, за которые запись
  уже есть (в любом статусе), в календаре помечены и недоступны; на уровне
  БД это гарантирует `INSERT … ON CONFLICT DO NOTHING` в `db.add_admin_entry`.
- **Отмена результата** (админ-панель → «🗑 Отмена результата»): поиск
  участника → календарь марафона (✅/⏳/❌ + пустые дни) → карточка дня
  (шаги, баллы, статус, кем внесён) → «🗑 Отменить» (`db.delete_entry`,
  день освобождается) с подтверждением или «↩️ Вернуть на проверку»
  (`db.reopen_entry`, только если есть скриншот). После обоих действий —
  `recompute_streak` + `recompute_weekly_bonus` и пуш участнику. Доступно
  всем админам (`settings.is_admin`).
- **«Тайный челлендж»** (админ-панель → «🎲 Тайный челлендж», роутер
  `bot/handlers/challenge.py`, таблица `challenges`, один день — один
  челлендж): множитель ×2/×3 на день для ВЫБРАННЫХ команд (пустой
  `team_ids` = все). Условие — весь день либо «после HH:MM», и это время
  **отправки результата**: времени самих шагов бот не знает (участник шлёт
  одно число за день) — так и написано в UI и в анонсе. Множитель
  применяется в `mod_accept` и в ручном вводе через
  `db.challenge_multiplier`; при создании/удалении челленджа уже принятые
  за день результаты пересчитывает `db.recount_day_points`. Анонс уходит
  только участникам выбранных команд.
- **«Командный флешмоб»** (админ-панель → «🤝 Командный флешмоб», роутер
  `bot/handlers/flashmob.py`, таблицы `flashmobs` + `team_bonuses`): если
  `threshold_pct` состава команды сдали за день принятый результат от
  `min_steps`, команда получает `bonus_points` — это КОМАНДНЫЕ очки, личные
  баллы не меняются. Учитываются третьим слагаемым в `db.team_leaderboard`.
  Пересчёт идемпотентный (`db.recompute_flashmob`) и вызывается после каждой
  правки результатов дня через `admin_settings._flashmob_sync` — модерация
  идёт вразнобой, поэтому расписание не используется. Бонус так же снимается,
  если условие перестало выполняться; поздравление уходит только при переходе
  «не выполнено → выполнено» (`res["new"]`).
- **Отчёт по активностям** (админ-панель → «📊 Активности и участие», роутер
  `bot/handlers/activities.py`, только чтение): список запущенных челленджей
  и флешмобов, по каждому — условие, команды, статус пуша, статистика
  участия (сколько доступен, сколько сдали, сколько попало под множитель /
  выполнило условие, сколько доп. баллов и командных очков) и поимённый
  список по командам. Данные — `db.day_participation` + `db.list_*`.
- **Регистрация**: /start → правила+согласие → телефон (только свой
  контакт) → ФИО → команда (5 мест) → заявка админам с Approve/Reject.
  До Approve участник не допускается к сдаче шагов.
- **Лидерборды** (бот, /leaderboard, пн 10:00, Mini App): команды + общий
  топ-10 участников. Раздельные женский/мужской топы были и убраны по
  просьбе заказчика — в Mini App подиум переиспользован под тройку лидеров
  общего зачёта.
- **Пол** — вспомогательное поле `participants.gender` ('f'/'m'/NULL):
  заполняется эвристикой `backend/gender.py` при регистрации и на старте
  (`db.backfill_genders`, трогает только пустые), правится кнопкой «⚧ Пол»
  в карточке участника, выгружается колонкой «Пол» в Excel. В лидербордах
  НЕ участвует.
- **Остановка активностей**: «📊 Активности и участие» → карточка активности
  → «⏹ Остановить и отменить» (любая дата, не только сегодня). Челлендж:
  `delete_challenge` + `recount_day_points(day, None)` — удвоенные баллы
  возвращаются к обычным. Флешмоб: `delete_flashmob` — снимает и
  `team_bonuses`. Если пуш об активности уже уходил, участникам её команд
  отправляется уведомление об отмене (`texts.challenge_cancelled` /
  `flashmob_cancelled`).
- **Сброс марафона** (`/admin` → «🧨 Сброс марафона», только для владельцев
  (env `ADMIN_IDS` + назначенные в «👑 Админы»), доп-админам кнопка не показывается и колбэк закрыт):
  экран со счётчиками → подтверждение словом `СБРОС` заглавными →
  `db.wipe_marathon()` одной транзакцией чистит participants, daily_entries,
  weekly_summaries, streaks, team_bonuses, challenges, flashmobs, broadcasts,
  scheduled_broadcasts. Порядок важен: broadcasts/scheduled_broadcasts имеют
  FK на participants. Команды, настройки, каналы, админы и оформление
  остаются — перезапуск не ломает конфигурацию.
- **Картинки дня WE GROW** (`bot/daily.py`, `assets/daily/NN.png`, 11 слайдов):
  расписание — смещения от `marathon_start` (пн/ср/пт, «Выходной на ногах» —
  сб, финальный — последний день), job `send_daily_card` в 09:00 всем
  активным. Файл грузится в Telegram один раз → file_id в settings
  `daily_fid_NN`; отметка `daily_sent_NN` = «дата:получателей» (сброс
  марафона её стирает). Нет файла — день пропускается. Админ-панель →
  «🖼 Картинки дня»: расписание, статусы, превью себе.
- **Фирменное оформление** (`bot/brand.py`, `assets/brand/menu.jpg` и
  `avatar.jpg` — иллюстрация «Стартуем!» без надписей): на старте разово
  (флаги `brand_menu_v1`, `brand_avatar_v1`) ставит картинку главного меню
  (`menu_media` = `{"type":"photo","asset":…}` → после первой отправки
  file_id, `bot/menu.py`) и аватар бота (`setMyProfilePhoto`). Повтор —
  «⚙️ Оформление» → «🪴 Фирменное меню: картинка + иконки» / «👤 Поставить
  аватар бота».
- **Reply-меню участника** (`keyboards.main_kb`): Шаги за сегодня,
  Еженедельный отчёт, Правила / Помощь, Обратная связь. Кнопки «Мой прогресс»
  и «Лидерборд» убраны по просьбе заказчика — прогресс и рейтинг смотрят в
  Mini App (кнопка «Открыть»); их хендлеры оставлены для старых клавиатур.
- **Главное меню** для подтверждённого участника — персональная карточка
  (`texts.profile_card(summary, today_entry, today)`): приветствие, фаза
  марафона («день 3 из 21» / «старт через N дней»), команда с местом,
  показатели в цитате, статус сегодняшнего дня (✅/⏳/❌/не сдано) и живая
  подсказка Stepy по ситуации.
- **Правила** (`texts._rules_body`): шапка + разделы-цитаты; баллы и бонус
  открыты, «Команды и зачёт», «Как сдавать», «Важно знать» — свёрнутые
  `<blockquote expandable>`.

## Важные соглашения

- **Премиум-эмодзи**: `EmojiMiddleware` на сессии бота (`bot/premium_emoji.py`,
  подключён в `main.py`) сам заменяет обычные эмодзи на `<tg-emoji>` во ВСЕХ
  исходящих HTML-сообщениях и подписях (не трогает готовые `<tg-emoji>`,
  атрибуты, `<code>/<pre>`, alert-ответы на колбэки и `parse_mode=None`;
  лимит 90 на сообщение). `pe()` размечает только Stepy 🪴 (`STEPY_ID`,
  не менять) — остальное подставляется при отправке. Карта «эмодзи → ID»:
  1) набор, подключённый админом командой **`/emojipack t.me/addemoji/ИМЯ`**
  (бот сам грузит набор через getStickerSet, хранит в settings `emoji_pack`);
  2) иначе `bot/emoji_ids.json` (+ `_fallback` — прежний рабочий iOS Icons),
  причём на старте `premium_emoji.validate` спрашивает Telegram
  (getCustomEmojiStickers) и оставляет только подтверждённые ID — ID обычных
  анимированных стикеров Telegram в тексте молча не показывает. Статус — в
  `/health` и логе старта. Иконки кнопок меню — `brand.use_default_icons`
  из текущей карты (флаг `brand_icons_v3`). Работает при
  `PREMIUM_EMOJI=true` и Premium у владельца. `texts.num` — системные кейкапы.
- **Порядок роутеров** в `bot/main.py`: `onboarding` ПЕРВЫМ (команды должны
  выходить из любых FSM-состояний), затем admin, admin_settings, steps.
- **Скриншоты**: принимаются и фото, и файлы-изображения; file_id документов
  хранится с префиксом `doc:`. В Excel колонка «Фото» — HMAC-подписанная
  ссылка `/shot/{entry_id}/{sig}` (см. `bot/export.py:shot_sig`), файл
  скачивается на сервере webapp — **токен бота в URL не попадает**.
- **Авторизация mini app**: приоритетно Telegram initData (HMAC + проверка
  `auth_date` ≤ 24 ч против replay), fallback — вход по номеру телефона:
  подписанный токен сессии с TTL 30 дней в localStorage, `/api/login` под
  rate limit (10 попыток / 10 мин с IP). `/api/me` и `/api/team` отсекают
  дисквалифицированных и неподтверждённых.
- **Старт бота не должен падать из-за косметики**: `commands.setup_all`,
  кнопка меню Mini App и `delete_webhook` обёрнуты в try/except — они идут
  ДО `start_polling`, и раньше сбой Telegram (429/5xx/сеть) на них валил
  процесс, а Render крутил перезапуск: снаружи это выглядело как «бот
  молчит». `TelegramConflictError` логируется отдельной строкой: его причина
  — второй запущенный экземпляр. В логе на старте печатается живая
  конфигурация (TZ, сегодня, даты марафона, число админов).
- **`/health`** (админы) — самодиагностика прямо в Telegram: таймзона и
  текущее время, даты и фаза марафона, открыт ли приём шагов, счётчики
  участников/результатов/команд/активностей, каналы и URL Mini App. Первое,
  что нужно спросить у бота, если кажется, что он не отвечает.
- **Напоминания в `bot/scheduler.py` включены** и защищены `_marathon_active()`:
  шлются только в даты марафона (даты из config). Задачи: 20:00 серия под угрозой,
  21:00 не сдал шаги, вс 12:00 анонс отчёта / 22:00 открытие / 23:15
  last-call, вс 23:55 бонусы, пн 10:00 лидерборд.
- **Кнопка «Сдать» в Mini App** открывает бота ссылкой `?start=steps`, и
  `cmd_start` с этим payload сразу зовёт `steps.start_steps_flow` (тот же
  вход, что кнопка «👟 Шаги за сегодня»). Мини-апп закрывается сам:
  `openTelegramLink` на ТОТ ЖЕ чат клиент игнорирует, и без `tg.close()`
  визуально «ничего не происходит».
- **Дедлайн сдачи — 23:55** (`bot/handlers/steps.py:_day_closed`), после —
  `texts.DAY_CLOSED`. **Анти-дубль**: `daily_entries.screenshot_unique_id`,
  при совпадении админ видит предупреждение. **09:00 — дайджест P&C**
  (`pc_daily_digest`), **23:59 — Excel-бэкап админам** (`nightly_backup`).
- **Еженедельный отчёт**: кнопка «📈 Еженедельный отчёт» работает только в
  вс 22:00–23:55 (`steps.py:_weekly_window`); принимается один скриншот
  недельной статистики Google Health → `weekly_summaries.screenshot_file_id` +
  `reported_at` (повтор заменяет файл, бонусы не трогает). Пуши: вс 12:00
  анонс, 22:00 открытие, 23:15 last-call не сдавшим. В Excel — лист
  «Недельные отчёты» со ссылками `/wshot/{id}/{sig}`.
- **Webapp**: разделы «Правила» и «Помощь» — аккордеоны (`acc()` в
  index.html), первый раздел правил открыт по умолчанию. Клиентские даты —
  только из серверных полей (`is_today`/`future`, номер дня из ISO-строки),
  НЕ через `new Date()` — иначе сдвиг в таймзонах западнее Ташкента.
  Race при переключении вкладок гасится токеном поколения `renderGen`.
  Внешние ссылки — через `tg.openLink` (`openExt()`).
- **Перекрытие навигацией (решено, НЕ регрессировать)**: нижний отступ под
  фиксированную навигацию живёт на `.wrap` (растёт с контентом), а НЕ на
  `body`; у body только `min-height:100%` — с `height:100%` контент вытекает
  и padding-bottom body не защищает последние элементы. Высоту панели
  подставляет `fitNavPadding()` в `--nav-h`.
- **Суб-агент `webapp-agent`** (`.claude/agents/webapp-agent.md`): все задачи
  по Mini App — через него; перед работой самообновляется из
  docs.telegram-mini-apps.com, github.com/telegram-mini-apps и
  core.telegram.org/bots/webapps.
- **Приложение шагов — Google Health (бывший Fitbit)**: во всех текстах бота и
  webapp фигурирует Google Health; принимается ТОЛЬКО скриншот страницы «Шаги»
  с фильтром «Все источники». Команда админа **/instruction** — рассылка
  инструкции (текст + 2 карусели iPhone/Android из `assets/instruction/`,
  превью с подтверждением; file_id кешируются после превью).
- **Предупреждение о неактивности** — команда админа **/inactive**:
  превью `texts.INACTIVITY_WARNING` + выбор адресата (только молчуны 2+ дня
  по `db.silent_ids`, либо все активные). Пишется в `broadcasts`
  (audience `silent`/`all`).
- **Отложенные рассылки**: кнопка «⏰ Отложить отправку» в билдере /broadcast,
  список/отмена — /scheduled. Хранятся в `scheduled_broadcasts` (draft jsonb),
  отправляет job `send_due_broadcasts` раз в минуту.
- **Дисквалификация**: `disqualified_at` не стирает записи — все зачётные
  запросы фильтруют `p.disqualified_at IS NULL` на лету (лидерборды, топ,
  `participant_summary`, `team_members`, вовлечённость, дайджест, очередь
  модерации, все рассылки и напоминания), поэтому `usrun:`/♻️ Восстановить
  возвращает баллы целиком. Accept на карточке дисквалифицированного
  отклоняется (`mod_accept`), запись остаётся `pending`. В Excel такие
  участники идут в конце листа со статусом «дисквалифицирован».
  При добавлении НОВОГО агрегата по `daily_entries`/`weekly_summaries`
  join к `participants` с этим фильтром обязателен.
- Телефоны участников видны только P&C. Все упоминания «ASR» заменены на
  «наша дружная компания / наш дружный коллектив».

## Как запустить локально / проверить

```bash
pip install -r requirements.txt
# локальный PostgreSQL, затем:
BOT_TOKEN=... DATABASE_URL=postgresql://... ADMIN_IDS=<id> python -m bot.main
# webapp:
uvicorn webapp.server:app --port 8000
# unit-тесты скоринга:
python -m pytest backend/test_scoring.py -q
```

Схема БД применяется идемпотентно на старте бота. Для сквозной проверки
логики удобно поднять чистую локальную БД и прогнать цепочку: регистрация →
сдача шагов → модерация → пересчёт серии/бонуса → выгрузка Excel.
